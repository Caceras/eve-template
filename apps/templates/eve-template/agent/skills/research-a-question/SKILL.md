# Researching a question

Search rather than answering from memory whenever the answer could have changed, was never in your training data, or is the kind of thing a person would want a source for. Use `web_search` to find sources and `web_fetch` only when a full page is genuinely needed.

## Decide what the question actually is

- A fact that moves ("what does X cost now"): one or two authoritative, recent sources. Do not read ten.
- A comparison ("X or Y for Z"): work out what actually differs before looking for who says what.
- A claim to check ("is it true that…"): find the primary source. A post repeating a press release is the same source, not a second one.
- A landscape ("what's happening with…"): breadth first, then depth on the two or three things that matter.

If the request is ambiguous between these, pick the most useful reading and say which one you picked.

## Read results before opening them

Open a page when its title or snippet suggests it answers the question, not because it is next in the list. Stop when you can answer well; a source that repeats what you have costs the user money and tells them nothing.

## What earns a source

Primary beats secondary. Recent beats old for anything that moves, but check the date. A source that disagrees with the others deserves more attention than a fourth that agrees; a disagreement in the evidence is part of the answer. If sources genuinely conflict and you cannot resolve it, say that.

## Cite as you write

Link the claim to the page it rests on with a Markdown link, for example "Anthropic shipped X in May ([announcement](https://…))". Never cite a page you did not read.

## Write the answer, not the search log

Answer in the first sentence, then support it. If nothing reliable exists, say so plainly; an invented source is worse than none.
