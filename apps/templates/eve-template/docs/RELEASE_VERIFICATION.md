# Release verification

The `release` field of `/api/health` (the `RELEASE` constant in `lib/release.ts`, also built into the app so an open app notices a newer release) identifies the product release; bump it with every release so a deploy is verifiable. The final merged commit and Dokploy deployment record identify the exact deployed source.

`/api/health` returns 200 with `ok: true` only when the app can serve a chat: the eve runtime answers (`eve: "ready"`), sign-in is set up (`app: "ready"`) and the chat database answers a read (`database: "ready"`; in Postgres mode, its schema check). Otherwise it returns 503 with `ok: false` and the failing field, so the image's Docker health check, CI's `image` job, `scripts/check-product.sh` and `pnpm verify:live` all fail on an unusable app instead of reporting it healthy. `scripts/test-health.mjs` covers each case.

## Required checks

The read-only CI workflow installs the frozen lockfile on Node 24 and runs `bash scripts/check-product.sh`: it fetches the upstream template baseline (`pnpm upstream:sync`, from `vercel/eve` main), then runs the isolated regression scripts (`pnpm test`, including the divergence check against that baseline), lint and format checks, the eve surface freshness check (`pnpm eve:surface:check`, which reads the live registry), eve compilation, Next.js type generation and checking, a Next.js production build, and Playwright Chromium acceptance. Explicit exit handling prevents successful log pipelines from concealing failed commands. A parallel `image` job builds the production `Dockerfile` with Buildx (cached in GitHub Actions) and starts the container with throwaway credentials on a volume seeded with a root-owned private file, as an older production volume has; it fails unless `/api/health` returns 200 with eve ready within about two minutes, every container process runs as `node` (uid 1000) and the seeded file now belongs to `node`, and prints the container logs when it does. CI has no production credentials or production data. Runs on pull requests are cancelled by a newer push; runs on `main` always finish.

Every workflow pins its actions to a full commit SHA with the release tag in a trailing comment, so a moved or hijacked tag cannot change what runs; Dependabot (`.github/dependabot.yml`, GitHub Actions only) opens a weekly pull request when a pinned action has a new release. The **Audit** workflow (`.github/workflows/audit.yml`) runs `pnpm audit --audit-level moderate` against the lockfile every Monday and on demand, with read-only permissions. A failed audit means a published advisory affects an installed package: update it, or add a narrow override in `pnpm-workspace.yaml`, as for drizzle-kit's esbuild.

## Runtime contracts

`app/(chat)/layout.tsx` resolves environment-dependent authentication, the viewer and history after `connection()` behind a Suspense boundary. The shell receives the same request-resolved initial values used for server rendering. Do not read Docker runtime credentials into a build-time shell placeholder: the image is built without those credentials and Dokploy supplies them later. The bootstrap synchronizer still reconciles navigation and history.

The product's `use-reliable-eve-agent` hook preserves the upstream `eve/react` store and callbacks. eve records failed sends in `onError` / the terminal snapshot rather than rejecting every `send()` promise. The wrapper surfaces those failures to the existing composer recovery path. Only successful sends clear attachments; rejected sends retain the files and text and release the busy state. Do not treat a resolved upstream send promise alone as inference success.

Saved agents are encrypted profiles of the operator workspace, not separate deployments or permission boundaries. Direct chat applies their instructions, reference context, reasoning and preferred model; an explicit composer selection wins over the profile default. Delegation uses a copy of the root agent and the current conversation model. Runtime tools retain their own approvals. See [Agents and orchestration](./AGENTS_AND_ORCHESTRATION.md).

Password sign-in checks the request's own host, so it works on every domain without extra configuration. After a deploy, check `/api/health` on both hosts.

## External verification

A working AI Gateway or OpenRouter key is supplied by the operator later. Real model responses, model/provider switching during a durable conversation, tool-approval continuation, saved-profile delegation and generated images require inference checks after that. Physical microphone/speaker behavior, the feel of the drawer under a real thumb and the color Android gives the gesture-bar strip need a device check. External integrations require their own credentials. No placeholder images or fake success states stand in for those checks.

Replace the legacy password through Settings > Security before adding credentials. See [Security and access](./SECURITY_AND_ACCESS.md). Password changes revoke old sessions without changing the settings encryption secret or erasing data.
